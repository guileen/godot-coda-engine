# 写出第一个游戏流程

先写一句你想让游戏发生的事，而不是先写回调：

> 玩家点击领取；奖励大于零时，积分数字从旧值动画到新值；动画结束后才进入下一步。

| 游戏里的意思 | CODA 写法 |
| --- | --- |
| 外部传来的值或节点 | 事件输入 |
| 这一步算出的结果 | `令` |
| 只有满足才继续 | `若` |
| 必须先完成的动作 | `等待` |

```coda
事件 领取奖励（当前积分，奖励，积分标签，动画时长） [标识：界面.奖励.领取]：
  令 新积分 为 当前积分 加 奖励
  若（奖励 大于 0）：
    等待 界面.播放数字动画@1(目标：积分标签, 起始值：当前积分, 结束值：新积分, 时长：动画时长)
```

这是中文别名预览；当前可执行版本仍在 [`examples/reward-claim.coda`](../../examples/reward-claim.coda)，使用项目契约里的机器标识。

括号里的输入让你和 AI 都能问出有用的问题：“这些值从 Godot 的哪个节点或系统传进来？”`等待` 表示动画是下一步的依赖，而不只是随意暂停。

```sh
npm run coda -- text-check examples/reward-claim.coda
npm run coda -- text-generate examples/reward-claim.coda
```

复杂算法、性能敏感循环和未声明的 Godot API 直接交给 GDScript。CODA 的价值是把容易失控的游戏流程变得可读、可检查。
