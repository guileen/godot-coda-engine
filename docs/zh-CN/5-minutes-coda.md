# 5 分钟认识 CODA

CODA 是给 Godot 独立开发者写**游戏流程**的语言。

当你想表达“玩家点领取后加积分，播放数字动画，动画结束再继续；界面消失时不要留下悬挂逻辑”时，不必先把这些散落在多个 `_process`、回调和临时变量里。把流程写成 CODA；CODA 会检查流程结构，并生成你仍然可以查看的 GDScript。

这不是让你放弃 GDScript。适合 CODA 的是条件、顺序、等待和 UI/玩法事件；独特算法或现成 Godot API 仍然可以留在普通 GDScript 中。

## 第一眼：一个领取奖励流程

打开 [`examples/reward-claim.coda`](../../examples/reward-claim.coda)。它的意思就是：

```coda
# 中文别名预览：玩家点下“领取奖励”后：加分、播放数字动画、再继续流程。
模块 界面.奖励
事件 领取奖励（当前积分，奖励，积分标签，动画时长） [标识：界面.奖励.领取]：
  令 新积分 为 当前积分 加 奖励
  若（奖励 大于 0）：
    等待 界面.播放数字动画@1(目标：积分标签, 起始值：当前积分, 结束值：新积分, 时长：动画时长)
    执行 界面.设置文本@1(目标：积分标签, 内容：新积分)
    发出 战斗.命中已结算@1(奖励)
```

上面展示的是中文别名的目标写法；现在可执行的示例仍使用项目契约中的机器标识，可从 [`examples/reward-claim.coda`](../../examples/reward-claim.coda) 打开。

读法不需要背：

1. `事件` 是一个可从游戏里触发的流程。
2. `令` 给这一步得到的值起名字。
3. `若` 只在条件成立时继续。
4. `等待` 明确告诉 CODA：下一步必须等动画完成后才发生。

这就是 CODA 的重点：**先把游戏发生的顺序说清楚，再让工具生成实现。**

## 试着改一件事

把奖励事件加一行 `令 奖励 为 奖励 加 10`，或者把等待的动画能力换成你的已声明能力。然后如果你有 Node.js 20+，在仓库根目录运行：

```sh
npm run coda -- text-check examples/reward-claim.coda
npm run coda -- text-generate examples/reward-claim.coda
```

第一条会指出不清楚的流程；第二条会在 `.gseos/generated/` 里生成 GDScript 和对应的 source map。生成结果是输出，不要直接手改。

如果你让 AI 帮你写，可以给它这样的约束：

> 用 CODA 写一个“玩家领取奖励”的事件：先判断奖励大于 0，再更新积分，等待 UI 数字动画结束后继续。只使用 `事件`、`令`、`若`、`等待` 和已声明的能力。

之后先运行 `text-check`，再把它接入你的 Godot 场景。

## CODA 与当前 Godot 工作流

目前的编辑器插件仍以事件树和 `.gse.json` 资产作为稳定的项目内工作流；CODA 文本可以用于快速表达、检查与生成。换句话说，你可以先用可读的流程语言和 AI 协作，再保留结构化资产、生成代码和 GDScript 的可追踪性。

想在 Godot 中打开现成项目并查看事件树，请继续读[快速开始](quick-start.md)。想知道哪些能力目前可用、哪些复杂逻辑仍应交给 GDScript，请读[核心概念](concepts.md)。
