# Security policy

Do not report suspected vulnerabilities in a public issue. Use GitHub private vulnerability reporting or the private contact mechanism configured by the repository maintainers.

Include the affected commit or version, reproduction steps, expected and observed behavior, and whether the issue affects authoring, generated code, runtime ownership/cancellation, or export boundaries. Do not include credentials or private user data.

Reports are especially useful when generated code or an `escape` node can bypass declared inputs/outputs, cause arbitrary Godot reflection, access an invalid owner, or settle a managed run more than once.
