A language for Godot indie developers

Make complex game flow easy to say.

CODA lets you write what happens in your game—conditions, UI changes, and waits across frames—before it becomes GDScript you can inspect.

The moments that get messy

Your game is a sequence of things.
Say that sequence directly.

01

Claim a reward

Add the score, play the number animation, then reveal the next reward. If the UI closes, the flow stops cleanly.

02

Finish a dialogue beat

Wait for a line, an animation, and a player choice before the next story event can begin.

03

Change a game screen

Remove the old UI, create the new state, and publish the next event in a readable order.

A small language, not a new wall

Write the flow.
Keep the intent visible.

CODA starts with a handful of familiar ideas: an event, a value, a condition, an action, and a wait. It is deliberately small so you and an AI can reason about the same flow.

  1. 01You describe the flow

    “If the reward exists, update the score and wait for its animation.”

  3. 02CODA checks it

    Conditions, named values, declared actions, and waits stay explicit.

  5. 03Godot runs it

    CODA generates GDScript you can read, trace, and ship with your game.

You stay in control

Use CODA where flow is hard.
Use GDScript where craft is yours.

Let CODA hold the flow

  • Conditions, sequence, and named values
  • Waits that must finish before the next step
  • UI and game events with visible boundaries
  • Generated code you can trace back to the flow

Keep GDScript for the special parts

  • Unique game algorithms and custom systems
  • Direct use of the Godot APIs you already know
  • Anything outside the current CODA vocabulary
  • Debugging and final control over your project
