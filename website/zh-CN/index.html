容易变乱的那些时刻

游戏是一连串发生的事情。
把它直接说出来。

01

领取奖励

加积分，播放数字动画，再展示下一份奖励。UI 中途关闭时，流程干净地结束。

02

完成一段对话

等台词、动画和玩家选择全部结束，下一段剧情事件才可以开始。

03

切换游戏界面

移除旧 UI，创建新状态，再按可读的顺序发出下一个游戏事件。

一门小语言，不是一堵新墙

写下流程。
让意图始终可见。

CODA 从几个熟悉的概念开始：事件、值、条件、动作和等待。它刻意保持小巧，让你和 AI 都能围绕同一段游戏流程思考。

  1. 01你说清流程

    “奖励存在时更新积分，并等数字动画完成。”

  3. 02CODA 检查流程

    条件、命名的值、已声明动作和等待都保持明确。

  5. 03Godot 运行它

    CODA 生成你能阅读、追踪并随游戏发布的 GDScript。

掌控权始终在你

流程难的地方交给 CODA。
独特的创作仍交给 GDScript。

让 CODA 管好流程

  • 条件、顺序和命名的中间值
  • 必须等上一步完成的跨帧等待
  • 边界清晰的 UI 与游戏事件
  • 能回到原始流程的生成代码

把特别部分留给 GDScript

  • 你的独特算法与游戏系统
  • 你已经熟悉的 Godot API 直接调用
  • 当前 CODA 词汇之外的逻辑
  • 项目最终的调试与控制权
